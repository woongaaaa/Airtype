# 개발 로드맵

기준: 8주 약 240시간. 사용자가 허용한 6~8주·주 25~35시간 내에서 6주차 통합, 7~8주차 검증·배포를 목표로 한다. 일정은 정확도 보장이 아니다.

| 단계 | 작업 | 완료 조건 | 현재 |
|---|---|---|---|
| 1주 | PRD·카메라·양손·키 이벤트·실험 도구 | 실제 손 자료와 실제 앱 한글 입력 | 문서/코드 구현, 실기기 검증 대기 |
| 2주 | 보정·누름·행 구분·엔진 비교 | 초기 CER/오입력 기준, 엔진 ADR | 도구 준비, 측정 대기 |
| 3~4주 | 열 손가락 안정화·기본키·한영·재생 | 미학습 문장과 혼합키 내부 빌드 | 규칙 기반 기준 구현 |
| 5주 | 포인터·드래그·스크롤·스와이프 통합 | 상태 충돌과 복구 시험 | 코드/단위 테스트 구현 |
| 6주 | 권한·온보딩·오버레이·패키징 | 통합 빌드·개발 DMG | 구현 및 로컬 빌드 |
| 7주 | 외부 5명·2종 Mac 평가 | 사용자별 결과와 수정 PR | 참가자 미확보 |
| 8주 | 회귀·서명·공증·릴리스 | release-gate 전체 충족 | 미충족 |

코드가 미리 구현되어 있어도 앞 단계의 실험을 통과한 것으로 표시하지 않는다. 2주차 실패 시 기능 확장을 멈추고 인식/자세/보정 개선에 집중한다. 4주차에도 실패하면 원인을 정리하고 출시 일정을 다시 산정한다. 화면 키 선택형으로 제품 목표를 바꾸지 않는다.

## 이슈 단위

1. 실제 손 세션 수집과 좌우/좌표 검증
2. Vision 대 MediaPipe 동일 자료 비교, 엔진 결정
3. 기본 키/열 손가락/숫자·기호 정확도 개선
4. TextEdit·Safari·Chrome의 한글·조합키 호환성
5. 포인터 과제와 추적·카메라·포커스 복구 실기기 검증
6. 일반 사용자 모집, 장비·OS 검증
7. Developer ID, 공증, 깨끗한 환경에서 DMG 설치

각 이슈는 가설·재현 조건·합격 기준·관련 PR·측정 결과를 포함한다. 연구 실패도 결과로 기록하며 통과하지 않은 항목은 닫지 않는다.
